# Стратегия защиты данных компании «Медикаменте»

---

## 1. Классификация данных

Данные классифицированы по четырём параметрам: **состояние**, **чувствительность**, **профиль риска** и **правовое основание обработки**.

### 1.1. Состояния данных

| Состояние | Описание | Примеры в «Медикаменте» |
|-----------|----------|------------------------|
| **Data at Rest** (данные в покое) | Данные, хранящиеся на носителях без активной передачи | Excel-файлы на файловом сервере, базы 1С, сканы документов (JPG, PDF), архивы |
| **Data in Transit** (данные в движении) | Данные, передаваемые по сети | Трафик между ККМ и сервером (TCP/IP + 1С OLE), email через Exchange, запросы к API лаборатории, обращения мобильного приложения к серверу |
| **Data in Use** (данные в использовании) | Данные, обрабатываемые в оперативной памяти или активно открытые | Excel-файлы, открытые сотрудниками; медкарты, просматриваемые врачом; отчёты, формируемые бухгалтером |

---

### 1.2. Классификация данных по чувствительности и профилю риска

| Класс | Уровень чувствительности | Профиль риска | Правовое основание | Данные в «Медикаменте» |
|-------|--------------------------|---------------|--------------------|------------------------|
| **Класс 1 — Критический** | Специальная категория ПДн | Максимальный: утечка влечёт уголовную и административную ответственность по ст. 13.11 КоАП, ст. 137 УК РФ; штраф до 15 млн руб. (152-ФЗ) | ст. 10 п. 4 152-ФЗ (медицинская помощь) | Диагнозы, медицинские карты, результаты анализов, рецепты и назначения, хронические заболевания, результаты лабораторных исследований |
| **Класс 2 — Высокий** | Персональные данные, идентифицирующие лицо | Высокий: риск мошенничества, кражи личности; штраф до 6 млн руб. | ст. 6 ч. 1 п. 5 152-ФЗ (договор) + согласие | ФИО + дата рождения, паспортные данные, СНИЛС, ИНН, телефон, email, адрес прописки, полис ОМС/ДМС, данные банковских карт |
| **Класс 3 — Средний** | Данные ограниченного доступа | Средний: репутационный и финансовый ущерб, коммерческие потери | Коммерческая тайна, договор | Зарплаты и кадровые данные сотрудников, суммы платежей пациентов, контракты, данные контрагентов, стоимость закупок |
| **Класс 4 — Низкий** | Внутренние данные | Низкий: незначительный ущерб от раскрытия | Внутренний регламент | Расписание врачей (без привязки к пациентам), справочники ТМЦ, нерезультирующие метрики |
| **Класс 5 — Публичный** | Общедоступные данные | Отсутствует | — | Адрес клиники, режим работы, общий прайс-лист |

## 2. Обоснование необходимости защиты

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|---------------------------|-------------------|
| **Диагнозы и медицинские карты** | Специальная категория ПДн (ст. 10 152-ФЗ). Утечка: штраф до 15 млн руб., уголовная ответственность по ст. 137 УК РФ, потеря лицензии. Доступны всем сотрудникам на общем диске без разграничения | BitLocker (шифрование диска), EFS (шифрование файлов), RBAC через AD (только лечащий врач), аудит доступа (Windows Audit Policy), DLP (блокировка копирования), MIP-метки |
| **Результаты лабораторных анализов** | Специальная категория ПДн. Хранятся в открытых Excel-реестрах. При интеграции с API лаборатории — риск перехвата данных | TLS 1.2+ для API, OAuth 2.0/OIDC для авторизации, шифрование файлов (EFS), RBAC (доступ — врач + пациент), Apache Atlas для Data Lineage |
| **ФИО + дата рождения + телефон + email пациентов** | ПДн: основа для идентификации личности. Хранятся в открытых Excel-файлах на общем диске без контроля доступа. Нарушение ст. 19 152-ФЗ | BitLocker, RBAC (ресепшен, врачи), Dynamic Data Masking в интерфейсах, Presidio для автодетекции PII, политика Data Minimization |
| **Паспортные данные, СНИЛС, ИНН** | ПДн высокого уровня: основа для мошенничества и кражи личности. Хранятся как сканы без классификации и контроля | EFS/MIP-шифрование сканов, RBAC (только бухгалтер/HR), политика NO_COPY, аудит доступа |
| **Данные банковских карт** | PCI DSS: хранение в открытом виде — прямое нарушение стандарта. Финансовые потери клиентов и компании | Не хранить (pass-through)! Certified Payment Gateway, TLS 1.2+, токенизация, аудит транзакций ККМ |
| **Зарплаты и кадровые данные сотрудников** | ПДн + коммерческая тайна. Хранятся в 1С в файловом режиме (нет разделения ролей на уровне БД). Внутренние конфликты, нарушение трудового законодательства | Перевод 1С на клиент-серверный режим (PostgreSQL + TDE), RBAC (только бухгалтер), Transparent Data Encryption |
| **Email-переписка с данными пациентов** | Конфиденциальные данные (диагнозы, ФИО) передаются в теле писем без шифрования. Нарушение принципа минимизации данных | S/MIME для Exchange, DLP-политики (блокировка вложений с ПДн), запрет передачи медицинских данных по email |
| **Данные контрагентов (поставщиков)** | ПДн контактных лиц + коммерческая тайна (цены, реквизиты). Доступны всем сотрудникам на общем диске | RBAC (только склад/бухгалтер), шифрование папок, аудит доступа |
| **Логи и история операций** | Отсутствие логов не позволяет расследовать инциденты и доказать правомерность обработки данных (ст. 19 152-ФЗ) | Windows Audit Policy, ELK Stack, SIEM (Wazuh), Victoria Metrics + Grafana |
| **Данные на мобильных устройствах / рабочих станциях** | Сотрудники могут копировать данные на локальные диски и USB без контроля | GPO (блокировка USB), MDM для мобильных устройств (если используются), BitLocker на рабочих станциях |

## 3. Инструменты защиты данных

### 3.1. Защита данных в покое (Data at Rest)

| # | Инструмент | Что защищает | Класс данных | Приоритет |
|---|-----------|-------------|-------------|-----------|
| 1 | **BitLocker (Windows Server + рабочие станции)** | Полное шифрование дисков. Защита от физического доступа к серверу и ПК | Все классы | Критический |
| 2 | **EFS (Encrypting File System)** | Шифрование отдельных файлов и папок на уровне NTFS | Класс 1, 2 | Критический |
| 3 | **Microsoft Information Protection (MIP)** | Классификация и шифрование файлов (Excel, PDF, JPG) с метками конфиденциальности | Класс 1, 2 | Высокий |
| 4 | **Transparent Data Encryption (TDE) в PostgreSQL** | Шифрование данных в базе данных при переходе 1С на клиент-серверный режим | Класс 1, 2, 3 | Средний (To-Be) |
| 5 | **Vault** | Централизованное управление ключами шифрования, секретами и сертификатами | Все классы | Высокий (To-Be) |

### 3.2. Защита данных при передаче (Data in Transit)

| # | Инструмент | Что защищает | Класс данных | Приоритет |
|---|-----------|-------------|-------------|-----------|
| 6 | **TLS 1.2+ для всех сетевых соединений** | Шифрование трафика: ККМ → сервер, 1С → БД, API-запросы к лаборатории, веб-порталы | Все классы | Критический |
| 7 | **S/MIME для Exchange Mail Server** | Шифрование и подпись электронной почты с конфиденциальными данными | Класс 1, 2 | Средний |
| 8 | **VPN (IPsec/SSL VPN)** | Защищённый канал между главным офисом и филиалами | Все классы | Высокий (при открытии филиалов) |
| 9 | **OAuth 2.0 + OIDC** | Безопасная авторизация для API лаборатории, мобильного приложения, клиентского портала | Класс 1, 2 | Высокий (To-Be) |
| 10 | **API Gateway (Kong / nginx)** | Единая точка входа с rate limiting, аутентификацией и логированием всех API-запросов | Класс 1, 2 | Высокий (To-Be) |

### 3.3. Защита данных в использовании (Data in Use)

| # | Инструмент | Что защищает | Класс данных | Приоритет |
|---|-----------|-------------|-------------|-----------|
| 11 | **RBAC через Active Directory (группы безопасности + ACL)** | Разграничение доступа по ролям: Врачи, Ресепшен, Кассиры, Бухгалтерия, Склад, ИТ | Все классы | Критический |
| 12 | **Dynamic Data Masking** | Обфускация данных в интерфейсах в зависимости от роли (ФИО → Иванов И.И., телефон → +7***123) | Класс 1, 2 | Высокий |
| 13 | **ABAC (Attribute-Based Access Control)** | Управление доступом: врач видит только своих пациентов в рамках своего отделения | Класс 1 | Высокий (To-Be) |
| 14 | **Row-Level Security в PostgreSQL** | Ограничение видимости строк в БД на уровне СУБД по атрибутам пользователя | Класс 1, 2 | Средний (To-Be) |

|---|-----------|---------|-----------|
